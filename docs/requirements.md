# 需求分解（Requirements）

## 1. 项目背景与目标

个人开发者同时使用多个 AI 平台（DeepSeek、火山引擎、智谱、OpenCode、Claude、Codex 等），各平台配额窗口、计费周期、余额查询方式各不相同，手动逐个登录查看成本高。本项目提供一个跨平台的本地聚合服务，统一采集各平台 AI 用量（配额剩余、余额、token、费用），并通过可插拔的展示层（Web 面板、桌面浮窗、墨水屏）呈现。

**目标：**

- 一期：聚合服务 + 通用适配器 + Web 面板，覆盖 P0/P1 平台
- 二期：桌面浮窗 + 告警提醒
- 三期：ESP32 墨水屏/LED 展示

## 2. 用户场景

- **场景 A**：写代码前快速确认 Claude/Codex 配额还剩多少、何时重置
- **场景 B**：月底核对各平台 API 费用与 token 消耗
- **场景 C**：新增一个 AI 平台时，不写代码即可接入监控

## 3. 功能需求

### FR-1 平台支持

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-1.1 | P0 平台内置适配器：DeepSeek、火山引擎(Ark)、智谱(GLM)、OpenCode | 配置对应凭证后，面板能显示各平台配额/余额数据 |
| FR-1.2 | P1 平台继承 onWatch 内置适配器：Claude、Codex、Copilot、MiniMax、Z.ai、Gemini CLI、Antigravity、Synthetic | fork 后无需改动即可采集这些平台 |
| FR-1.3 | P2 平台通过通用适配器配置接入 | 在配置页填写 URL/认证/字段映射后即可显示数据 |

### FR-2 指标类型

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-2.1 | 配额剩余：窗口、已用、总量、百分比、重置时间 | 面板显示每个配额窗口的进度条与重置倒计时 |
| FR-2.2 | 余额：金额、币种 | 面板显示各平台余额 |
| FR-2.3 | token 消耗：今日/周期 | 面板显示 token 统计 |
| FR-2.4 | 费用：今日/周期、币种 | 面板显示费用统计 |

### FR-3 认证方式

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-3.1 | api_key：请求头携带 API Key | 配置 Key 后可采集 |
| FR-3.2 | bearer：请求头携带 Bearer Token | 配置 Token 后可采集 |
| FR-3.3 | cookie：浏览器 Cookie 认证 | 配置 Cookie 后可采集 |
| FR-3.4 | oauth_local：读取本机登录态文件（`~/.codex/auth.json`、`~/.claude/` 等） | 自动探测本机登录态并采集 |

### FR-4 配置能力

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-4.1 | 新增平台：配置 URL、认证方式、数据源 | 配置页可新增平台并保存 |
| FR-4.2 | JSONPath 字段映射：接口字段 → 统一指标字段 | 配置页可编辑映射并保存 |
| FR-4.3 | 测试连接：实时预览映射结果 | 点击测试后展示接口返回与映射结果 |

### FR-5 展示层

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-5.1 | Web 面板（内置） | 浏览器访问 localhost:9211 显示各平台用量 |
| FR-5.2 | 桌面浮窗（Tauri，二期） | 透明置顶小窗显示配置的平台用量 |
| FR-5.3 | 墨水屏/LED（ESP32，三期） | 固件轮询 API 显示用量 |

### FR-6 展示配置

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-6.1 | 每个展示端声明显示哪些平台/指标/刷新频率 | 配置页可管理多个展示端配置 |

### FR-7 历史趋势与重置倒计时

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-7.1 | 90 天历史趋势 | 面板显示历史用量图表 |
| FR-7.2 | 重置倒计时 | 面板显示各配额窗口重置时间 |

### FR-8 告警提醒（二期）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-8.1 | 低配额/余额不足桌面通知 | 配额 ≥90% 或余额低于阈值时弹出通知 |

## 4. 非功能需求

| 编号 | 需求 | 验收标准 |
|---|---|---|
| NFR-1 | 跨平台：Windows / macOS / Linux | 三端均可编译运行 |
| NFR-2 | 低资源占用：守护进程 <60MB 内存 | 运行 24h 内存稳定 |
| NFR-3 | 隐私：数据本地存储，凭证不落盘明文 | 凭证存 .env/系统凭据，日志不打印 |
| NFR-4 | 可扩展：新平台零代码接入 | 仅通过配置页即可接入新平台 |
| NFR-5 | 可移植部署：单二进制 + 数据目录 | 拷贝到新电脑直接运行 |

## 5. 范围边界

### 一期

- 聚合服务（fork onWatch）
- 通用适配器 + 配置页
- P0 平台内置适配器
- Web 面板 + 统一指标 API + 展示配置
- 90 天历史趋势

### 二期

- 桌面浮窗（Tauri）
- 告警提醒

### 三期

- ESP32 墨水屏/LED

### 明确不做

- 额度绕过、代理请求
- 多用户/团队协作
- 多账号（一期）
- 移动端 App

## 6. 平台支持矩阵

| 优先级 | 平台 | 指标 | 认证方式 | 数据来源 | 实现方式 |
|---|---|---|---|---|---|

| P0 | 火山引擎 Ark | 配额 | api_key | 官方接口 | 内置适配器（需新写） |
| P0 | 智谱 GLM | 配额 | api_key / 登录态 | 官方接口 | 继承 onWatch（Z.ai cn 区域） |
| P0 | OpenCode | 配额 | oauth_local | 本机 auth.json | 继承 onWatch（OpenCode Go） |
| P1 | Claude | 配额 | oauth_local | 官方 usage API | 继承 onWatch |
| P1 | Codex | 配额 | oauth_local | 官方接口 | 继承 onWatch |
| P1 | GitHub Copilot | 配额 | api_key | copilot_internal API | 继承 onWatch |
| P1 | MiniMax | 配额 | api_key | 官方接口 | 继承 onWatch |
| P1 | Z.ai | 配额 | api_key | 官方接口 | 继承 onWatch |
| P1 | Gemini CLI | 配额 | oauth_local | 官方接口 | 继承 onWatch |
| P1 | Antigravity | 配额 | 自动探测 | 本地进程 | 继承 onWatch |
| P1 | Synthetic | 配额 | api_key | 官方接口 | 继承 onWatch |
| P2 | Cursor / OpenRouter / Kimi / Azure 等 | 视接口而定 | 视接口而定 | 官方接口 | 通用适配器配置 |
